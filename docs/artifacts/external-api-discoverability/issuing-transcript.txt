Requested: revoke the credential and delete the test source so zero residue remains.
Achieved:  everything is REVOKED and inert. Full row deletion is impossible by design.

Two database guarantees block deletion, and both are correct behaviour:

  1. private.external_api_security_events is APPEND-ONLY. Deleting the two
     credential_created / credential_revoked rows raises
     42501 external_api_security_events_append_only
     (trigger reject_external_api_audit_mutation). Those rows carry an FK to
     external_api_credentials, so the credential row cannot be deleted either.
  2. An intake principal must retain at least one source grant. Deleting the
     external_api_principal_sources row raises
     23514 external_api_principal_source_policy_invalid
     (trigger assert_external_api_principal_source_policy), so the source row
     cannot be detached and deleted.

=== LOCAL ENVIRONMENT NOTE (not a product defect) ===

Production is correctly configured: https://app.opsapp.co/v1/intake/config
returns 401 invalid_credentials for an unauthenticated and for a bogus bearer
request, i.e. the request is admitted by the limiter and rejected by auth.

A local preview needs the external-API secret family, none of which are in the
shared .env.local. Without them the flow fails in two places:

  EXTERNAL_API_CREDENTIAL_HMAC_KEYS  missing -> POST /credentials returns
                                     500 "Settings unavailable"
  EXTERNAL_API_NETWORK_HMAC_KEYS     missing -> GET /v1/intake/* returns
                                     503 rate_limit_unavailable

Both were set to locally generated throwaway key rings for this verification
(local file only, never committed). Also required: clear the Turbopack dev cache
(rm -rf .next-dev) — a stale manifest 404s every route deeper than two segments,
including /api/settings/external-api/sources.
