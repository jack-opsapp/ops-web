## Retry and loss contract

`stage_tryops_experiment_signup(p_token,p_actor_id)` stores assignment ID and actor, never a plaintext bearer. An acknowledged `pending/no_exposure` is durable; engine reconciliation owns later attachment. `retry_tryops_experiment_trial(p_actor_id,p_company_id)` uses that binding even without a browser cookie. Engine SQL independently requires ownership, membership, eligible exposure and original trial timing, and deduplicates company/assignment outcomes.

An unacknowledged initial stage has a 1 second request budget. Next `after()` runs three further bounded attempts after response close, with 100/300/700ms pauses and 1 second RPC timeout each. It stops on any durable or terminal acknowledgement. Its closure retains only the server database client, canonical actor, and bearer in request memory. A successful retry never records collection loss. A memoized callback prevents duplicate execution within the request.

Exhaustion calls `report_tryops_collection_failure(p_key,p_reason,p_assignment_id,p_token_hash,p_actor_id)` with deterministic dedupe key, `signup_staging_failed`, null assignment ID, SHA256 token hash, and verified canonical actor. The engine must resolve a known assignment and active actor inside SQL, map the exact experiment, and reject unknown/mismatched evidence with zero experiment mutation. Web treats `recorded`, `rejected/invalid_assignment`, and `rejected/invalid_actor` explicitly. Tokens, hashes, actor IDs, request bodies, and raw database errors are never logged by this helper or returned to the browser.

Logs distinguish `recovery required`, `loss excluded`, and `measurement loss` with `persisted:true|false`. Terminal logs include the durable dedupe correlation key, a separate digest of the actor and token hash that cannot serve as an assignment bearer or lookup hash. A total database outage or unavailable Next scheduler cannot guarantee delivery. A persisted loss invalidates its exact experiment through the engine's inference guard. Any `measurement loss` with `persisted:false` is an operator gate: hold experiment decisions/publication for the affected observation interval until logs and persisted bindings are reconciled. Missing evidence must not become zero conversions or an apparently healthy cohort. Do not fabricate a company/assignment or invalidate an arbitrary active experiment from an unmatched cookie. The app continues signup; operator review concerns measurement integrity.
